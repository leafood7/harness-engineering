# 文件读取契约、有限输入纠错与摘录复测

本轮仍属M6候选验证，默认策略保持stable.v1，未经明确要求不做Git提交、暂存、推送或发布。

## 四组对照

- stable.v1：原有工具说明，读取错误按原规则停止。
- file-contract.v1：明确read只接受普通文件，目录及工作区根目录不是文件；仍不允许错误后继续。
- read-correction.v1：同一文件契约，对确认无副作用的特定读取输入错误，允许模型修改参数再调用。
- anchored-correction.v1：同一有限纠错，加上有界原文摘录。

候选定义和来源在strategies/profiles.json。前三组使用证据索引压缩，最后一组使用短原文摘录。契约组与纠错组使用同样的文件工具说明，避免把说明与纠错机制的效果混为一谈。没有增加目录枚举、Shell或文件访问权限。

## 哪些错误可以纠正

仅允许治理器已经确认失败、工具名为read、outcome=no_effect，且错误为EISDIR、ENOENT或ENOTDIR的调用。宿主把它作为isError=true的结构化工具结果返回，告诉模型输入类型和剩余额度，随后由模型选择新的文件参数。

这不是自动重试旧参数。失败操作仍为failed，原始错误仍可检查；每个后续调用重新走范围、权限、审批（仅当原配置为ask）、工具次数、时间和费用控制。工具失败不是任务成功，最终仍需独立验收。

每个Run最多两次输入纠错提示，跨所有followups共用，恢复时继承已消耗额度和待处理引用。相同无效目标再次失败会直接停止；第三个不同无效目标也会停止。成功读取不会重置额度。没有剩余工具预算时不再花模型请求让它纠错。

取消、权限拒绝、越界、超时、未停稳、未知结果、瞬态错误和所有写入/编辑失败都不走这条路径。已有瞬态重试规则仍由原治理器管理，不与模型输入纠错混用。写入错误即使有同样的EISDIR码，也保持不确定副作用的保守处理。

## 真实失败与回执

read.correction_offered记录真正失败的读取、错误码、目标摘要和已用额度；只有宿主产生的一次性回执才能让相应的isError工具事件继续，模型不能靠结果文本伪造许可。read.correction_followup记录之后真正成功的读取及对应待处理提示。它表示发生了有效后续读，不自动证明某一个根因已被解决。

额度更新和事件同事务保存；持久化失败不授予回执。恢复预检会检查额度账本格式，不能把异常状态变成新的两次额度。

## 新固定题与实验范围

fixed-agent-tasks.v3-read-input-and-retention保留上轮八题，新增：

1. 目录输入练习：如果目录输入被拒或契约不允许，改读任务明确给出的guide.txt。
2. 缓存读取回退：先尝试cache.json，不可用时读source.json，禁止编造或创建缓存。
3. 分段事实：多个观察、多个干扰阶段，保留数字0、布尔false和中文字段。
4. 较长原文：接近但不超过单条摘录上限，事实位于段落中部。
5. 超限原文：超过单条1200字节边界，测量明确省略后的表现。

共13题、4组、每题每组2次，共104次真实任务。保留题均记录最终问题前的原生压缩和事实标记可见性，答案不在原始目标、初始文件或其他记忆中；同时检查没有额外笔记。离线预写输出仅验证流程，不能当作保留能力分数。

所有组相同模型、温度、权限、预算、任务和评分器。同题、同重复号、同组别配对，计划与门槛提前冻结，失败保留且不选择性重跑。报告增加readInputErrors、readCorrectionOffers和readCorrectionFollowups：任务成功与中间工具错误分开计算，不能把错误隐藏在成功率里。

默认费用上限为整批1美元的SDK目录估算值，非供应商账单保证。请求、失败后的新模型调用和工具尝试都计入同一预算。出现未确认用量时仍停止整批。

## 复现与边界

```powershell
npm run benchmark:read-correction-smoke
npm run benchmark:read-correction
npm run harness -- strategy compare <batch-directory>
```

结果满足工程门槛最多只进入review_candidate，不会切换默认版本。两个重复、有限合成题不足以证明普遍可靠性；原文摘录不是语义总结，超限观察仍可能丢失。真实收益、回归和不被触发的机制都需要按实际结果报告。
