13题、四组、每题两次，任务/模型/预算相同。以下保留原始固定检查器的全部成绩，包括事后发现题面存在歧义的目录练习，不能把这张表当成完全无歧义的能力排名。

104次合计64次任务成功、40次失败，662530 Token、374次宿主请求，总SDK目录估算费用约0.137214美元。费用不是账号实际账单，耗时和费用包含失败早停。

相邻配置的配对差异更能说明本轮目标：

- 明确文件契约，相比默认多完成两次多模块修改，未观察到配对退化；费用约增加9.7%。
- 在相同文件契约下允许有限纠错，多完成两次缓存缺失回退，未观察到配对退化；费用约增加6.5%。
- 再加入原文摘录，多完成六次压缩保留题，未观察到配对退化；费用约增加7.9%。

这些是有限合成题上的观察，不是统计显著性或一般任务可靠性证明。每题仅两次，不能宣称目录误用或长任务已被普遍解决。

## 目录练习的题面问题与独立确认

原目录题只说把value写到result.json，没有明确要求带value键的JSON对象，而固定检查器要求该对象。四次纠错成功的调用都读到了正确文件，却写成正确的纯文本代码，因此在固定格式检查中失败，另两项检查通过。

这暴露出题面不够明确，不能把这四次都归因于模型的格式理解错误。原104次成绩没有改写。protocol-notes.json记录了问题；剔除该题的结果只作事后敏感性参考，不能据此回填分数或改判原来的采纳门槛。

另建directory-input-schema，明确JSON对象及唯一属性value，并对所有四组各做三次真实确认：

| 配置 | 新题成功 | 纠错提示/后续有效读 |
|---|---:|---:|
| 默认 | 0/3 | 0/0 |
| 只说明契约 | 0/3 | 0/0 |
| 有限纠错 | 3/3 | 3/3 |
| 纠错＋摘录 | 3/3 | 3/3 |

确认题累计6/12成功，41668 Token、30次宿主请求，估算费用约0.008053美元。它单独保存，不与原104次合并计算成功率。题目主动要求尝试目录输入，因此这里只证明发生输入错误之后的受控恢复，不等于自然任务中的目录错误频率。

## 摘录独立复测的边界

本轮原生压缩实际触发151次。原有短观察、分段观察（含0、false、中文字段）、较长但在1200字节内的原文，组合候选合计6/6成功，最终问题前的事实标记均可见；其他三个索引摘要组为0/6。

超过单条1200字节的观察，所有组都是0/2，标记都不可见。组合组汇总保留题为6/8，不应写成“所有长材料都保住了”。这符合当前有界摘录设计，仍需更广的内容、长度与任务测试。

## 评审判断与未解决问题

组合候选相对默认的总估算费用增加约26.1%，超过预先固定的25%门槛，结果是tradeoff_requires_review，没有通过成本筛选。门槛没有事后修改，也没有因为成功更多就自动启用。

文件契约和有限纠错达到当前工程review_candidate条件，但不是统计证明或自动采纳。默认仍是stable.v1，所有候选的automaticAdoption=false。

原批次40次失败包括17次独立验收失败、18次工具执行失败、5次越界拒绝。纠错没有把越界变成可访问路径；失败后的错误提示、模型新调用和工具尝试都计入原预算。读取错误仍为isError，失败操作仍为failed。写入、权限、超时和结果不确定的操作没有获得自动重试。
