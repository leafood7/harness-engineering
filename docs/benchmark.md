# 固定任务评测与经验记录

这套评测量化当前 Harness 配合指定真实模型的表现，不使用模型自己的成功声明评分，也不自动把失败诊断变成规则。

## 固定什么、比较什么

固定任务集 fixed-agent-tasks.v1 包含四题：

| 题目 | 类别 | 独立检查 |
|---|---|---|
| arithmetic-repair | 普通代码任务 | 正数、负数、零、小数加法 |
| order-aggregation | 普通数据任务 | 结构/排序、去重汇总、源文件不变 |
| long-evidence | 普通长材料任务 | 正确提取指定事实、源文件不变 |
| shipping-memory | 依赖维护资料的任务 | 当前工作区约定、源文件不变 |

最后一题的约定是人工构造的资料，保存在试验记忆中，不是读取或发送用户真实项目的私密设置。它用于检查资料是否能按范围送达模型。必须单列结果，不能把得到额外信息后通过该题解释成普遍推理能力提升。

四个组别：baseline 关闭工具文本投影压缩、原生压缩和记忆检索；context 仅启用两种上下文处理；memory 仅启用记忆；combined 两者启用。所有组仍保留相同的系统提示、目标提示、工具权限、上下文容量限制、输出预留、时间/工具/Token/费用预算与独立评分。关闭上下文处理不表示关闭安全控制。

默认真实配置为 DeepSeek deepseek-flash、temperature=0、thinking=off、每题每组两次，共 32 次。固定种子打乱试验顺序，相同题目和重复号用于配对比较。温度为零不等于完全确定，服务端权重也没有被固定；API缓存、网络和顺序影响仍可能存在。

每次创建新的工作区、Run、状态库和记忆库。仅复制夹具文件到工作区，评分器在工作区外冻结。工具路径控制阻止读取外部评分器；这仍不是操作系统沙盒。记忆库同时种入无关资料和其他工作区的错误资料，用于核实检索范围。

plan.json 记录完整配置、顺序、固定任务和评分器摘要、运行时源码摘要。每次试验前检查这些摘要，变化则停止该批次。运行期间修改测试或说明文档不会改变模型输入；修改运行源码、依赖锁文件或固定任务会停止继续调度。新批次不会覆盖旧批次，失败题不会自动重跑或挑选最好结果。

## 怎么运行

```powershell
npm run benchmark:plan
npm run benchmark:smoke
npm run benchmark:live
npm run harness -- benchmark run benchmarks/deepseek-flash.json --output D:\VScodeProgects\harness-engineering\.artifacts\my-benchmarks
npm run harness -- benchmark report <batch-directory>
```

smoke 使用预写输出的本地脚本模型，只检查管线和边界，不是能力分数。长材料原始组可能因既定容量限制失败，失败留在报告中。

live 从 DEEPSEEK_API_KEY 环境变量读取密钥。当前只向固定 SDK 模型对应端点发送自建夹具和任务；不读用户全局模型凭据，不发送用户笔记或现有项目。密钥不写入配置、报告或日志。模型目录可见性与一次单题接入检查另存，不混入正式 32 次的统计。

当前 DeepSeek 接口与价格参照 [官方模型价格页](https://api-docs.deepseek.com/quick_start/pricing/) 和 [官方调用说明](https://api-docs.deepseek.com/quick_start/)，查询参考保存在 benchmarks/model-reference.json。运行报告记录固定 SDK 的模型目录、上下文窗口、价格和版本；文档的型号说明不是冻结权重的证明。

## 怎么计分

成功必须同时满足 Run=completed 且独立 Verification=passed。每题分数是通过的预先固定检查项数除以该题总检查项数；没有到达验收阶段的试验记 0 分。保留所有已尝试试验，包括失败和中断；未开始的试验列为覆盖缺口，不悄悄算成通过或失败。

报告给出每组成功率及 95% Wilson 区间、普通题与资料依赖题分表、每题分组结果、平均分、平均/P50/P95执行时长、Token、目录价格估算费用、请求与压缩次数，以及配对成功/Token/费用差异。执行时长包括 Session 初始化、执行和独立验收，不含准备夹具与记忆的时间。小样本P95只是描述值。

记忆结果同时记录选中条数、相关条数、人工标记下的精确率和召回率；没启用记忆的组不是检索算法失败，应结合组别开关理解。相关性标记是固定题的人工真值，只覆盖这些资料，不能推广到任意用户记忆。

Token 来自 SDK 转发的供应商用量。费用是固定 SDK 目录价格计算值，不是账号账单，缓存与峰谷时段会影响实际扣费。缺失用量用 null 表示，不当作零；发生未确认的模型用量会停止整批继续调用。请求计数是宿主 dispatch 次数，不保证等于所有底层 HTTP 尝试数。

默认整批估算费用上限 1 美元、累计 Token 上限 500000，每个任务最多 0.025 美元估算费用。请求前用偏保守的输入估算和输出上限检查剩余费用，响应后再按 SDK 用量记账。上限依赖目录价格和估算口径，不是对供应商账单的保证；不要用它替代供应商账号级费用限制。取消会停止后续调度并向当前 Run 发出取消。

## 证据和经验如何保存

每批 .artifacts/benchmarks/batch-* 下保存 plan.json、benchmark.sqlite、report.json、report.md 和隔离的 trials。SQLite 是试验结果与经验记录的权威来源；report 可重建，原始 Run 里仍保存 Session、工具操作、检查器输出和事件。

trial 结果按唯一键追加，带内容摘要，不能用后来一次成功覆盖前一次失败。开始执行前落下 activeTrial 标记，异常退出后可发现未完成项；本版本不自动重放这种试验，应先检查对应 Run。

失败分类仅依据真实状态、宿主错误类别和独立检查结果。经验记录关联 Run、失败检查名和事件序号；diagnosis 为 null、not_established，eligibleForAutomaticPolicy=false。这些是待分析的观察，不是已经验证的根因，更不是可自动生效的规则。下一阶段的候选策略与对照实验再处理诊断验证和采纳。

原始状态库、Session、完整日志和运行工作区不上传 GitHub。可发布的基线仅包含合成任务定义、评分器、脱敏指标和证据引用，不包含密钥或模型完整对话。

这套小型固定题集用于建立第一份可追踪的真实模型基线。即使某组全通过，宽置信区间、重复之间相关性、任务选择和服务端变化都限制结论；不能据此宣称模型在一般任务上达到相同比例，也不能仅凭总体平均值采纳策略。
