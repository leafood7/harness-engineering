# 策略版本管理、切换与回滚

本轮交付的是可用功能。策略效果比较仍是独立工作，本轮没有新增真实模型评测或付费调用。

## 常用操作

在项目目录运行。未指定 `--state` 时使用项目的 `.harness`；不同状态目录分别管理策略。

```powershell
node bin/harness.mjs strategy list
node bin/harness.mjs strategy current
node bin/harness.mjs strategy inspect read-correction.v1
node bin/harness.mjs strategy switch read-correction.v1 --reason "下一批任务启用有限读取纠错" --expected-revision 0
node bin/harness.mjs strategy history
node bin/harness.mjs strategy rollback --reason "恢复上一个策略" --expected-revision 1
```

`--expected-revision` 是可选的并发保护：版本号与当前不符时不切换。省略时按取得写锁后的最新状态执行。理由必填，用来回答以后为什么改过配置，不是额外的审批流程。

`list` 显示内置初始默认版本、当前选择以及各版本的职责配置、候选状态、来源和内容摘要。候选版本可以由使用者明确选择，但不会因此被标为稳定版本或自动通过效果门槛。

## 生效范围

- 未写 `task.strategy` 的新任务，在开始执行时读取一次当前策略。
- 明确写了 `task.strategy` 的任务优先使用指定版本。
- 任务保存完整 `strategy.json` 和摘要，开始后不会追随默认选择变化。
- 中断恢复核对原版本和检查点绑定，不查询当前默认版本。原策略文件或对应目录定义改变时拒绝恢复。
- 新状态目录从 `stable.v1` 开始。本轮没有修改用户实际运行目录的默认选择。

## 原子保存与回滚

独立的 `strategies.sqlite` 使用 SQLite 写事务，同步保存当前指针、递增修订号和历史；失败一起撤回。多个进程通过写锁串行修改，可用预期修订号防止覆盖别人刚做的选择。登记过的版本绑定内容摘要，不允许同名改内容；新配置应使用新版本 ID。

回滚选择最近一次变更前的版本，并新增历史，保留旧记录。连续回滚会在最近两个选择间切换；返回任意已知版本可直接 `switch <id>`。回滚只影响未来任务，不撤销已有工具写入，也不迁移运行数据。

版本定义仍由项目内的受约束目录管理，不提供任意 JSON 配置导入、跨机器发布或自动晋升。内置 `stable.v1` 的约束保持不变。摘要用于发现改动，不是防御有权直接篡改数据库的攻击者。

## 兼容范围

当前应用版本为 0.8.0。恢复机制继续拒绝跨应用版本恢复；历史 0.7.0 任务需在对应原运行版本下处理。本轮修复的是同一运行版本中，策略默认选择变化导致的恢复问题。

## 功能检查

使用离线脚本化模型检查实际任务启动、切换期间版本锁定、新任务选版、显式覆盖以及恢复沿用旧版本；另外检查保存失败整体撤回、版本内容冲突、回滚和并发修订保护。最终统一运行类型检查及项目回归，不以此推断真实模型效果。
