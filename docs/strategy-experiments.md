# 候选策略与分阶段对照

本轮把评测从“比较开关”推进到“比较独立版本的候选策略”。所有结果仅保存在本地；未经明确要求，不做 Git 提交、推送或 GitHub 发布。

## 固定的候选与默认策略

strategies/profiles.json 定义三个独立版本：

| 策略 | 变化 | 不变化 |
|---|---|---|
| stable.v1 | 当前默认：证据索引压缩、无额外读取建议 | 权限、预算、检查器 |
| range-read.v1 | 增加先读小范围、按线索读取的提示建议 | 压缩仍用证据索引 |
| anchored-summary.v1 | 原生压缩时保留有来源的短原文摘录 | 没有额外读取建议 |

候选带未验证假设和上一轮基线/局限引用，引用可核查。策略只改变受控提示建议或摘要形式，不能增加工具权限、工作区范围、执行预算或改变评分器。默认策略仍是 stable.v1，候选结果不自动激活。

每个 Run 写入 strategy.json，Run 保存策略摘要，检查点绑定文件摘要。恢复会拒绝策略漂移。通过 `strategy list`、`strategy inspect <id>` 查看版本，通过 `strategy compare <batch-directory>` 查看配对结果和评审判断。

## 扩充后的固定任务

fixed-agent-tasks.v2 保留原四题，增加多模块发票计算、最新修订与假值/删除语义、正确报告缺资料、原生压缩后事实保留，总共八题。新题和评分器在正式对照前冻结，没有根据正式结果调整。

缺资料题把按约定报告 blocked 视为正确完成，避免把合理的不猜测误写成推理错误。原有 shipping-memory 题仍单列为资料依赖题。

默认对照在相同 combined 组内比较三个策略，每题重复三次，共72次真实任务。相同题目、重复号、组别配对；固定种子交错顺序。模型、温度、权限和任务预算相同。每个策略有24个任务结果，不能与上一版四题样本直接做前后成功率比较。

## 原生压缩后的保留题如何避免假通过

该题分四个提示执行：准备、提供短暂观察、加入长干扰材料、最后提问。观察中的标记只在后续提示出现，原始目标和初始工作区都不含答案，其他记忆也没有该答案。中间要求只确认，不得提前写文件或回显事实；最终检查同时验证答案和没有额外笔记。

Pi 自动压缩发生在安全提示边界。记录最终问题前的压缩次数，并从当时的原生检查点重建上下文，检查观察标记是否仍然可见。只发生压缩但原文还在窗口里，不足以证明跨压缩保留。基线与小范围读取策略使用索引摘要；摘录候选保留短原文作为参考资料。

离线脚本模型在每次调用时生成响应时间戳，而不是启动时一次生成全部时间戳；否则后续响应会被Pi判断为早于压缩的旧用量，从而跳过后续自动压缩。离线结果只验证流程，不计算真实模型的事实保留成绩。

摘录最多16条，总序列化预算6000字节，单条原文最多1200字节；过长资料明确计入省略数。跨轮携带有内容摘要的旧摘录并去重。这是有界原文保留，不是语义理解，也不是持久化长期记忆；有恶意内容的摘录仍是数据，不能改变当前指令或权限。

## 分阶段任务和恢复

Task 支持可选 followups 数组。一个任务内所有提示共用同一Session、同一累计预算，只有最后提示停稳后才独立验收。Run记录 nextPromptIndex/promptInProgress，检查点保存相同进度。恢复跳过完整完成的提示；当前提示中断时从持久化会话继续，不重复之前完成的写入。

完成提示进度尚未进入匹配检查点时，恢复明确拒绝跳过，不把“收到完成事件”当成已经可靠落盘。旧版本Run仍按原规则拒绝跨版本恢复。

## 预先固定的评审门槛

strategies/review-policy.json 随计划冻结：至少16个配对、6道不同题；不允许有配对失败回归；估算费用最多增加25%，平均时长最多增加50%；至少增加一次成功，或在不降低成功率时估算费用降低至少10%。

这些是工程评审筛选条件，不是统计显著性证明。结果可能是证据不足、拒绝回归、无改善、代价需要权衡或可供人工评审。任何结果的 automaticAdoption 都是 false，默认策略不变。报告同时列出所有胜负对应的Run，保留候选变差的情况。

任务执行用量不确定时停止继续调度。失败不自动挑选重跑，原始记录只追加。实际供应商费用与SDK目录估算并不等价，统计仍受缓存、网络、服务端变化与小样本限制。

## 命令与证据

```powershell
npm run benchmark:strategy-smoke
npm run benchmark:strategies
npm run harness -- strategy list
npm run harness -- strategy inspect anchored-summary.v1
npm run harness -- strategy compare <batch-directory>
```

每批仍保存冻结计划、SQLite试验/经验、Run和原生Session、JSON/Markdown报告。对照期间不改运行代码、候选目录、任务或评分器。另做独立审计，重跑固定检查并核对阶段进度、候选摘要、事实可见性、权限/预算相同与统计结果。

下一步应根据保留下来的胜负证据补充独立任务和验证假设，再进入明确的采纳/回滚流程；当前不因为一次通过就替换默认策略。
