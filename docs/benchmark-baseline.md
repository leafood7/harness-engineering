# DeepSeek 固定任务首轮基线

2026-11-02，Harness 0.5.0，真实 deepseek-flash，temperature=0、thinking=off。四题、四组、每题每组两次，共 32 次任务执行；正式样本不含离线检查和单题真实接入检查。

|---|---:|---:|---:|---:|---:|---:|
| 基础 baseline | 5/8 | 5/6 | 0/2 | 3301 | 4.19 | 0.005866 |
| 仅上下文 context | 6/8 | 6/6 | 0/2 | 5069 | 5.00 | 0.006846 |

所有组累计 138498 Token，93 次宿主模型请求，总目录估算费用约 0.026299 美元。费用包含失败试验，是固定 SDK 的用量估算，不是实际账单；接入检查另有约 0.000757 美元估算费用，没有混入表中。平均时长包含失败早停，不能直接解释为同等成功条件下的速度比较。

## 可以据此说什么

在这组受控任务和预算下，组合组比基础组多完成三次任务。两次来自获得完成项目约定题所需的记忆；另一次是长材料题在容量边界内成功完成。普通题的结果是 5/6 对 6/6，不是全部 37.5 个百分点都来自一般任务能力提升。

长材料题中，关闭上下文处理的两组各有一次触发宿主容量限制；另一次通过，说明真实模型也会选择不同的读取范围。启用上下文的组均通过该题，但本轮总体 Token 没有下降：组合组比基础组多用约 54.8% Token，目录估算费用多约 23.1%，同时完成了更多任务。不能说“压缩后一定更便宜”，更不能把失败早停造成的低费用当成效率优势。

记忆依赖题没有在工作区提供约定：不给记忆时未能完成，提供正确范围的记忆后完成。无记忆时不猜测约定也是合理行为，任务未完成不等于模型推理错误。启用记忆的四次该题均只检索到相关记录，未混入其他工作区的错误资料；此处精确率和召回率各为 1，只能说明这组人为标记资料的范围控制有效。

本轮记录了 19 次工具文本投影压缩，原生自动压缩触发 0 次。因此可以评估这套输入限制下的工具投影路径，不能据此量化原生语义压缩或证据索引长期保真效果。

## 不能据此说什么

每组仅 8 次、只有 4 道不同题目，而且重复之间并非完全独立。组合组虽然 8/8，其描述性 95% Wilson 区间仍约为 67.6%–100%；基础组约为 30.6%–86.3%。这些结果不足以声称普遍成功率达到 100%，也没有证明统计显著的因果改善。

失败集中在 2 次上下文容量停止和 4 次工具执行失败。后四次出现在缺少项目记忆的资料依赖题，记录为观察到的工具失败，不自动认定根因。当前小题集还没有充分覆盖复杂语义错误、多文件大改动或真正触发原生压缩后的事实丢失。

本机原始证据保存在 .artifacts/benchmarks/batch-htbFyo。其他机器可根据固定计划重新运行，新结果必须放到新批次，不能覆盖此基线。

建议下一轮扩充任务和重复次数，单独设计会真正触发原生压缩的事实保留题，再用预先固定的评分验证候选策略。当前结果可作为对照基线，尚不足以自动采纳新策略。
